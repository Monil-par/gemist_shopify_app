ANZA Gems – Shopify Marketplace
Developer Project Requirements Document
Hybrid Wholesale (B2B) + Retail (B2C) Gemstone Marketplace

1. Project Overview
ANZA Gems is a gemstone wholesaler currently operating on ShopWired. The objective of this project is to build a new Shopify-based marketplace that supports both wholesale (B2B) and retail (B2C) customer experiences in a single, unified storefront.
The client works closely with Gemist, which provides backend infrastructure and product data management. The new storefront must modernize the current platform while preserving the brand's emphasis on ethical sourcing, gemstone traceability, and East African artisanal mining partnerships.
The MVP focuses on storefront implementation, wholesale access control, product presentation, and Shopify commerce workflows. The build must follow the approved Figma designs exactly and be fully responsive across desktop, tablet, and mobile.
1.1 Business Goals
•	Modernize the existing storefront experience
•	Improve gemstone discovery and filtering
•	Support wholesale buyers and retail customers simultaneously in one Shopify store
•	Create scalable infrastructure for future marketplace growth
•	Simplify catalog and inventory synchronization workflows
•	Preserve brand storytelling around ethical sourcing, traceability, and community impact
1.2 Technical Goals
•	Implement the new storefront within the Shopify ecosystem (Standard plan)
•	Integrate cleanly with Gemist backend infrastructure for product data
•	Implement customer-type-based pricing logic (guest / retail / wholesale)
•	Create secure wholesale authentication and approval workflows
•	Support scalable product synchronization (CSV now, API later)
•	Build a performant, maintainable frontend that follows Figma exactly

3. Features & Functionalities
3.1 User Roles & Authentication
The site supports four functional user states. The role determines what is visible, what CTAs are active, and what the user can do.
Capability	Guest (Not Signed In)	Retail User (Signed In)	Wholesale User (Approved)	Pending Wholesale
Browse marketplace	Yes	Yes	Yes	Yes
View gem specifications	Yes	Yes	Yes	Yes
View pricing	No	Retail price only	Wholesale price	No
Save / Favorite stones	Prompts login	Yes	Yes	No
Add to cart / Request stone	Prompts login	Yes (retail)	Yes (wholesale)	No
Share Selected	Prompts login	Yes	Yes	No
Checkout	Blocked	Retail checkout	Wholesale checkout	Blocked
Read blog / About / CMS	Yes	Yes	Yes	Yes

Key behavior notes:
•	Authentication is part of the sales funnel, not just account management — every gated CTA pulls the user into a sign-in modal
•	The sign-in modal is reused throughout the site, triggered from listing actions, PDP actions, save/favorite, request, share, etc.
•	Sign-in modal copy: "Unlock Exclusive Wholesale Gems — Sign in to view wholesale pricing, add your favorite gemstones, select items for your order, and check out seamlessly, all in one place."
•	Login page also available as a standalone route with Email + Password fields, plus "Create Account" and "Forgot Password?" links
3.2 Wholesale Account Approval Workflow
Trade accounts are NOT auto-approved. The flow is:
1.	Customer fills out the trade application form (Register for a Trade Account page)
2.	Admin reviews the application in the Shopify admin (or via the B2B app's interface)
3.	If approved, the customer is tagged as a wholesale customer and gains: wholesale pricing visibility, full CTA access, wholesale checkout permissions
4.	If rejected or pending, the customer remains in a restricted state (can browse but cannot view pricing or purchase)

Implementation approach (since Shopify Standard, not Plus):
•	Use Shopify customer tags to mark wholesale vs. retail vs. pending
•	Use the chosen B2B app (SparkLayer or Wholesale Gorilla) for the wholesale pricing layer and approval workflow
•	Custom Liquid logic + customer tags drive the role-based visibility on the storefront
3.3 Pricing Visibility Logic
Pricing visibility is governed entirely by the customer's role tag at request time.
•	Guest (not signed in): No prices anywhere on the site. All price fields replaced with "Log in to view price" or hidden. Price filter on the marketplace is hidden or disabled.
•	Retail user (signed in, retail-tagged): Retail price visible on listing cards and PDP. Retail checkout available.
•	Approved wholesale user (signed in, wholesale-tagged): Wholesale price visible (with retail price shown as a secondary comparison reference per Figma — both Wholesale and Retail price shown on product cards). Wholesale checkout available.

Pricing display order on product cards (signed in):
•	Wholesale: $X,XXX (primary)
•	Retail: $X,XXX (secondary, where applicable per Figma)

3.5 Product Catalog & Data Management
Data flow (MVP):
•	Client supplies a product CSV
•	Developer imports the CSV into Shopify products + variants + metafields
•	Gemstone-specific attributes stored as Shopify product metafields (one metafield definition per attribute)

Future data flow (post-MVP):
•	Customer inventory → Gemist Backend → Shopify Product Sync → Shopify Storefront
•	API integration with Gemist replaces the CSV import
•	Source-of-truth for inventory remains in Gemist; Shopify mirrors it

Required product metafield namespace structure (recommended):
•	gem.type (string)
•	gem.color (string + linked color swatch reference)
•	gem.shape (string)
•	gem.size_mm (string, e.g., "6mm")
•	gem.carat (number_decimal)
•	gem.origin (string)
•	gem.cutter (single_line_text or reference to a metaobject)
•	gem.birthstone (string)
•	gem.availability_count (number_integer)
•	gem.gem_id (string — internal Gemist ID)
•	gem.retail_price (currency — if not handled via variant)
•	gem.wholesale_price (currency — handled via B2B app)
•	gem.description_color, gem.description_shape, etc. (multi_line_text for the expandable PDP rows)
